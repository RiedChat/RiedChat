# Настройка XMPP-сервера

RiedChat - обычный XMPP-клиент, работает с любым сервером, поддерживающим
нужные XEP. Ниже - что нужно включить на стороне сервера отдельно, потому
что без этого часть функций клиента не заработает или деградирует.

## Поддерживаемые XEP

XEP-0012, 0059, 0060, 0066, 0115, 0153, 0163, 0172, 0198, 0199, 0203, 0215,
0308, 0313, 0333, 0363, 0384 (OMEMO), 0420, 0447, 0454.

## TURN для звонков (XEP-0215)

Клиент запрашивает TURN/STUN у своего XMPP-сервера через XEP-0215
(`net/turn/extdisco.js`). Проще всего это получить на **Prosody** модулем
`mod_turn_external`:

```lua
modules_enabled = {
    -- ...
    "turn_external"; -- Provide external STUN/TURN service for e.g. audio/video calls
}

-- Адрес TURN-сервиса (можно тот же домен, что и у XMPP)
turn_external_host = "example.com"

-- Тот же секрет должен быть прописан в coturn (static-auth-secret)
turn_external_secret = "сгенерируйте_случайную_строку"

-- Порты должны совпадать с настройками coturn (turnserver.conf)
turn_external_port = 3478
turn_external_tls_port = 5349
```

`mod_turn_external` сам не поднимает TURN-сервер - рядом всё равно нужен
[coturn](https://github.com/coturn/coturn) с тем же `static-auth-secret` и
портами 3478/5349 (REST API временных credentials, HMAC-подход, описан в
[документации Prosody](https://prosody.im/doc/turn)). Как только это
настроено, extdisco вернёт клиенту рабочий TURN с временными credentials -
никаких дополнительных настроек в RiedChat не требуется.

Если на сервере XEP-0215 не настроен (модуль не включён/сервер - не
Prosody), клиент как крайний фоллбек сам попробует домен аккаунта (часть JID
после `@`) на портах 3478/5349 без credentials - сработает только если TURN
на этом хосте настроен на анонимный доступ; иначе звонок останется на голом
STUN и может не пройти через симметричный NAT.

## Загрузка файлов (XEP-0363)

Нужен включённый `http_file_share` (или отдельный компонент того же типа) -
без него загрузка и отправка файлов в чате не работает.

## История сообщений (XEP-0313, MAM)

Нужен включённый `mod_mam`. Без него клиент не сможет подгружать историю
переписки при входе с нового устройства/после переустановки.

## Push-уведомления о смене устройств OMEMO (XEP-0115 + PEP)

Для того чтобы клиент узнавал о новом/удалённом устройстве контакта без
ручного опроса, серверу и контактам нужна поддержка Entity Capabilities
(`mod_pep`, включён по умолчанию в актуальных версиях Prosody).
